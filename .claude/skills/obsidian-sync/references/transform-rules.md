# 변환 엣지 케이스 & 점검 항목

`transform-obsidian.js` 수정·디버깅 시 참조. 본문 SKILL.md의 "변환 규칙"을 보강한다.

## 코드 보호 메커니즘 상세

변환은 다음 순서로 동작한다:
1. 코드펜스(```` ``` ````) 블록과 인라인코드(`` ` ``)를 정규식으로 찾아 고유 플레이스홀더 토큰으로 치환하고 원문을 보관한다.
2. 나머지 텍스트에 변환 규칙(주석/위키링크/이미지/이스케이프 등)을 적용한다.
3. 플레이스홀더를 보관한 원문으로 복원한다.

**새 규칙을 추가할 때의 함정**: 규칙을 plain text 전체 문자열에 무심코 적용하면, 복원 전이라 플레이스홀더 토큰에는 안전하지만 — 만약 보호 추출이 불완전한 코드 형태(예: 들여쓰기 코드블록, 틸드 펜스 ` ~~~ `)가 있으면 보호되지 않는다. 현재 보호 대상은 백틱 펜스와 백틱 인라인코드다. 새 코드 표기를 지원하려면 보호 단계부터 확장한다.

## 위키링크 해석 엣지 케이스

- `[[파일#헤딩]]`, `[[파일#^블록]]` 형태의 헤딩/블록 참조가 포함된 위키링크는 현재 파일명만 slug로 떨어지고 앵커는 버려질 수 있다. 헤딩 deep-link가 필요하면 별도 규칙 추가 검토.
- 표시 텍스트에 `|`가 여러 개면 첫 `|` 기준으로 분리되는지 확인.
- `existingSlugs` 매칭은 frontmatter slug와 파일명 slug 둘 다 등록돼야 한다. 새 글이 위키링크로 안 잡히면 1패스 수집 로직부터 의심.

## 이미지 경로 엣지 케이스

- `Attached file/` 외에 다른 첨부 폴더명을 Vault에서 쓴다면 변환 규칙에 폴더명을 추가해야 한다.
- 공백·한글이 포함된 이미지 파일명은 URL 인코딩 여부를 확인. `public/images/`의 실제 파일명과 정확히 일치해야 404가 안 난다.
- 원격(http) 이미지는 변환 대상이 아니지만, `next.config.mjs`의 `remotePatterns`에 도메인이 없으면 next/image가 거부한다(현재 허용: imagedelivery.net, 지정 S3, media.vlpt.us).

## 코드펜스 언어 정규화 주의

` ``` mermaid` → ` ```mermaid` 변환은 **같은 줄의 공백만** 제거하도록 정규식이 개행을 매칭하지 않아야 한다. 개행까지 매칭하면 펜스 두 줄이 합쳐져 코드블록이 깨진다. 정규식 수정 시 멀티라인 플래그·`.`의 개행 매칭을 반드시 점검.

## frontmatter 처리 엣지 케이스

- `date`가 `YYYY-MM-DD HH:mm` 같은 형태면 날짜 부분만 정규화되는지 확인.
- tags가 빈 문자열/빈 리스트일 때 빈 배열로 떨어지는지(undefined 아님).
- `series`가 숫자/불린으로 들어오면 문자열로 강제되는지.

## 수정 후 검증 절차

1. 최소 재현 `.md`를 Vault의 `published/`(또는 임시 테스트용 별도 경로)에 두지 말고, 가능하면 변환 함수를 직접 호출하는 단위 확인을 우선한다.
2. `pnpm sync` 실행 → 콘솔의 변환 경고(잔여 `%%`/`[[ ]]`) 확인.
3. 대상 글의 `content/*.mdx` 출력과 `posts.json` 항목을 diff로 비교.
4. 변환 규칙을 바꿨다면 **기존 전체 글**에 회귀가 없는지(특히 코드블록 많은 글) 샘플 점검.
5. Vault 원본 파일을 만들거나 옮겨 테스트했다면 정리 시 `obsidian-safe-delete` 스킬 사용(rm 금지).
