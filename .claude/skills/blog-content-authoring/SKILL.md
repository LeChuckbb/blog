# 블로그 글 작성·발행 규칙

이 블로그는 Obsidian Vault의 `blog-content/published/` 에 쓴 마크다운이 `pnpm sync`로 `content/*.mdx` + `src/app/posts.json`으로 변환되어 발행된다. 글을 쓸 때는 변환 파이프라인이 무엇을 기대하는지 알아야 결과가 깨지지 않는다.

## 글이 놓이는 위치가 발행 여부를 결정한다

- **발행 대상**: Vault의 `blog-content/published/` 안의 `.md`/`.mdx`.
- **제외**: `blog-content/drafts/` 전체, 그리고 파일명이 `_`로 시작하거나 `.draft.`/`.temp.`를 포함하는 파일.
- 따라서 "초안 → 발행"은 본질적으로 파일을 `drafts/`에서 `published/`로 옮기는(또는 `_` 접두를 떼는) 행위다. 글 내용을 다 다듬었어도 위치가 틀리면 빌드에 안 들어간다.

## frontmatter — 무엇을 채워야 하나

파이프라인은 누락 필드를 자동 보정하지만, **자동 보정에 의존하면 SEO·정렬 품질이 떨어진다.** 직접 채울 것을 권한다.

| 필드 | 필수성 | 직접 채워야 하는 이유 |
|---|---|---|
| `title` | 강력 권장 | 없으면 파일명에서 생성됨 — 파일명이 제목으로 노출되는 사고 방지 |
| `date` | **사실상 필수** | 정렬·sitemap·RSS pubDate의 기준. 없으면 `1900-01-01` 취급되어 맨 뒤로 밀림. `YYYY-MM-DD` 형식 |
| `slug` | 선택 | 지정하면 URL `/posts/{slug}`가 됨. 한글 허용. 생략 시 파일명 기반 자동 생성 |
| `description` | 권장 | 메타·OG·RSS 설명. 생략 시 본문 첫 단락에서 자동 추출되지만 품질이 들쭉날쭉 |
| `tags` | 선택 | YAML 리스트 또는 콤마 문자열 모두 허용(콤마는 split됨). 카테고리/키워드 |
| `series` | 선택 | 시리즈로 묶을 때만. 아래 "시리즈" 참조 |

### slug 정규화 규칙

slug는 다음으로 정규화된다(직접 지정하든 자동 생성하든 동일): 소문자화 → 공백을 `-`로 → `영문/숫자/한글/-`만 유지 → 연속 하이픈 축약 → 양끝 하이픈 제거. 한글 slug는 그대로 유지된다.

**주의**: 출력 MDX 파일명은 slug가 아니라 **원본 파일명**이다. posts.json의 import 키는 파일명이므로, 이미 발행된 글의 **파일명을 함부로 바꾸면** import 매칭이 흔들릴 수 있다. slug만 바꾸고 싶으면 frontmatter `slug`를 수정하고 파일명은 유지하는 게 안전하다.

## description 작성

좋은 description은 검색 결과·OG 카드·RSS에 그대로 노출된다. 자동 추출 폴백 규칙(본문 첫 의미 단락, 20자 초과 첫 줄, 최대 155자에서 `...`)에 맡기기보다, **120~155자 내외로 글의 핵심을 한 문장으로** 직접 쓴다. 키워드를 앞쪽에 배치한다.

## 시리즈로 묶기

- frontmatter에 `series: "시리즈 이름"` 문자열 하나만 넣는다. **묶을 글들이 정확히 같은 문자열**이어야 그룹핑된다(오타·띄어쓰기 차이 = 다른 시리즈).
- 순서는 **date 오름차순**(동률이면 slug). 별도 순번 필드는 없으니, 순서를 의도대로 하려면 `date`로 제어한다.
- 멤버가 **2편 이상**일 때만 시리즈 내비게이션이 렌더된다. 1편짜리 series는 표시되지 않는다.

## 위키링크·이미지 작성 관례

작성 시 Obsidian 표준 문법을 그대로 쓰면 변환기가 처리한다. 다만 결과를 의도하려면:

- **위키링크 `[[글제목]]` / `[[글제목|표시텍스트]]`**: **게시된 글**만 내부 링크 `/posts/slug`로 해석된다. 미게시 글을 가리키면 비활성 텍스트(red link)가 된다. 의도적으로 깨진 링크가 아니라면, 가리키는 글도 함께 `published/`에 있어야 한다.
- **이미지 `![alt](Attached file/x.png)` 또는 상대경로**: `/images/x.png`로 변환된다. 해당 파일이 Next.js `public/images/`에 실제로 존재해야 한다. 원격(http) 이미지는 `next.config`의 `remotePatterns`에 도메인이 등록된 경우만 렌더된다.
- **콜아웃 `> [!note]`**: 빌드 플러그인이 처리하므로 표준 Obsidian 콜아웃 문법을 그대로 둔다.
- **주석 `%% %%`, 블록참조 `^id`**: 변환 시 제거된다. 발행 후 사라질 내용이니 본문 의미를 거기에 의존하지 않는다.

## 발행 전 체크리스트

글을 "발행 준비 완료"라 부르기 전에 확인:

1. 파일이 `published/`에 있고 제외 패턴(`_`/`.draft.`/`.temp.`)에 안 걸리는가
2. `title`, `date`(YYYY-MM-DD), `description`이 채워졌는가
3. slug가 의도한 URL인가 (한글이면 URL 인코딩 형태도 확인)
4. 위키링크 대상이 모두 게시되는가 (의도치 않은 red link 없음)
5. 참조 이미지가 `public/images/`에 있는가
6. 시리즈면 같은 series 문자열·date 순서가 맞는가
7. `pnpm sync` 후 `content/`에 .mdx가 생기고 posts.json에 항목이 들어갔는가

동기화 실행·변환 세부 규칙은 `obsidian-sync` 스킬을 참조한다. Vault 파일 삭제·이동은 `obsidian-safe-delete` 스킬을 사용한다(rm 금지).
