브라우저 렌더링 과정에서 브라우저의 렌더링 엔진은 HTML 문서를 파싱하여 브라우저가 이해할 수 있는 DOM 자료구조를 생성한다. \<span style="color:red">**DOM(Documnet Object Model)**\</span>은 HTML 문서의 계층적 구조와 정보를 표현한다. DOM은 개발자들이 해당 웹 문서를 쉽게 조작할 수 있도록 프로퍼티와 메서드를 API로 제공한다. \<span style="color:red">**DOM API**\</span>를 사용해서 DOM을 제어하는 방법을 배우기 전에, DOM의 기본 단위인 노드에 대해서 알아보도록 하자.

## 1. 노드Node
\<span style="color:red">**HTML 요소(HTML element)**\</span>는 HTML 문서를 구성하는 개별적인 묶음이다. HTML 요소는 브라우저 렌더링 과정에서 아래 그림과 같이 파싱되어 DOM을 구성하는 기본 단위인 노드로 변환된다. 이처럼, DOM은 \<span style="color:red">**노드Node**\</span>로 구성된다. 노드는 부모,자식,형제와 같은 계층적 구조를 갖는다. 따라서 DOM은 노드 객체의 계층적인 구조로 구성된다고 볼 수 있다.

![](https://my-personal-image-bucket.s3.ap-northeast-2.amazonaws.com/obsidian/images/velog-79df8480-af90-400e-bd32-ebfbdb5248ff-image.png)

### 노드 타입
노드 객체는 총 12개의 종류(타입)가 있는데, 이 중 중요한 노드 타입은 4가지다.

- **문서 노드Document Node** : DOM 트리의 최상위에 존재하는 루트 노드로서 document 객체를 가리킨다. \<span style="color:red">**document 객체**\</span>는 브라우저가 렌더링한 HTML 문서 전체를 가리키는 객체이며, 전역 객체 window의 documnet 프로퍼티에 바인딩되어 있다. 따라서 문서 노드는 window.document 혹은 document로 참조할 수 있다.
- **요소 노드Element Node** : HTML 요소를 가리키는 객체다.
- **어트리뷰트 노드Attribute Node** : 어트리뷰트 노드는 요소 노드와 형제sibling 관계를 맺는다 .따라서 어트리뷰트 노드에 접근하려면 먼저 형제 노드인 요소 노드에 접근해야 한다.
- **텍스트 노드Text Node** : 텍스트 노드는 자식 노드를 가질 수 없는 리프 노드leaf Node다. 즉, DOM 트리의 최종단이다. 텍스트 노드에 접근하려면 부모 노드인 요소 노드에 접근해야 한다.

### 노드 상속 구조

![](https://my-personal-image-bucket.s3.ap-northeast-2.amazonaws.com/obsidian/images/velog-569c5276-282a-4d7d-8b60-6c85c9bac24d-image.png)

위 그림과 같이 모든 노드 객체는 Object, EventTarget, Node 인터페이스를 상속받는다. 그리고 노드 타입에 따라 문서 노드는 Document, HTMLDocument를 상속받고 어트리뷰트 노드는 Attr, 텍스트 노드는 CharacterData 인터페이스를 상속받는 형식이다. 요소 노드는 특히 상속받는 인터페이스가 많은데, Element, HTMLElement와 태그의 종류별로 세분화된 HTMLhtmlElement, HTMLHeadElement.. 등을 상속받는다.

![](https://my-personal-image-bucket.s3.ap-northeast-2.amazonaws.com/obsidian/images/velog-e0091ac9-ff9b-48bc-901c-3423727185f7-image.png)

프로토타입 체인 관점에서 살펴보면 위와 같다. HTML의 input 요소를 파싱하여 객체화한 input 요소 노드 객체는 HTMLInputElement, HTMLElement, Element, Node, EventTarget, Object의 prototype에 바인딩되어 있는 프로토타입 객체를 상속받는다. **즉, input 요소 노드 객체는 프로토타입 체인에 있는 모든 프로토타입의 프로퍼티나 메서드를 상속받아 사용할 수 있다.**

모든 노드 객체는 EventTarget 인터페이스에 의해서 이벤트를 발생시킬 수 있다. 또한 모든 노드 객체는 트리 자료구조의 노드로서 트리 탐색기능이나 노드 정보 제공 기능이 필요한데, 관련 기능을 Node 인터페이스가 제공한다.

HTML 요소가 객체화된 요소 노드 객체는 HTML 요소가 갖는 공통적인 기능(예를들면 style 프로퍼티 같은)을 담고 있어야 한다. 이는 HTMLElemenet 인터페이스가 제공한다. 반면에 HTML 요소의 종류에 따라 고유한 기능도 있다. input 요소의 value 프로퍼티 같은 것 말이다. 이는 HTMLInputElement 인터페이스가 제공한다.

공통된 기능일수록 프로토타입 체인의 상위에, 고유 기능일수록 하위에 배치된 것을 볼 수 있다.

## 2. 요소 노드 취득하기

HTML을 조작하기 위해서는 요소 노드 취득이 선행되어야 한다. 요소 노드를 취득할 수 있는 메서드는 다음과 같다. HTML의 id/tag/class 등의 속성을 이용하거나 CSS Selector를 이용하여 해당 노드의 탐색 결과를 반환해주는 메서드다.

| 인터페이스  | 메서드명 | 반환 자료구조(복수형일 경우)        |
| :------------: | :-----------: | :-------------------: |
| Document     | getElementsById |  |
| Document/Element    | getElementsByTagName      | HTMLCollection               |
| Document/Element     | getElementsByClassName | HTMLCollection|
| Document/Element | querySelector |
| Document/Element | querySelectorAll | NodeList

### Document.prototype / Element.prototype
`getElementById`를 제외한 요소 노드 취득 메서드는 모두 Document 인터페이스와 Element 인터페이스에 정의되어 있다. Document 인터페이스에서 제공한 메서드는 DOM의 루트 노드인 문서 노드, 즉 document를 통해 호출하여 DOM 전체에서 요소 노드를 탐색해 반환한다. 하지만 Element.prototype.getElementsByTagName 메서드는 특정 요소 노드를 통해 호출하며, 특정 요소 노드의 자손 노드 중에서 요소 노드를 탐색하여 반환한다.

```html
<ul id="fruits">
    <li>Apple</li>
    <li>Banana</li>
    <li>Orange</li.
</ul>
<ul>
    <li>HTML</li>
</ul>

<script>
    // DOM 전체에서 태그 이름이 li인 요소 노드 모두를 탐색하여 반환
    const lisFromDocumnet = document.getElementsByTagName('li'); // 4개 li
    
    // ul#fruits 요소의 자손 노드 중에서 태그 이름이 li인 요소 노드 모두를 탐색하여 반환
    const fruits = document.getElementById('fruits');
    const lisFromFruits = fruits.getElementsByTagName('li'); // 3개 li
</script>
```

### DOM 컬렉션 객체 (HTMLCollection / NodeList)
함수는 하나의 값만 반환할 수 있으므로 여러 개의 값을 반환하려면 배열이나 객체와 같은 자료구조에 담아 반환해야 한다. 따라서 여러 개의 값을 반환하는 요소 노드 취득 메서드는 DOM 컬렉션 객체에 담아서 반환하는 형식을 취하고있다.

\<span style="color:red">**HTMLCollection**\</span>과 \<span style="color:red">**NodeList**\</span>는 모두 유사 배열 객체이면서 이터러블이다. 따라서 for...of 문으로 순회할 수 있으며 스프레드 문법을 사용해서 간단하게 배열로 변환할 수 있다. DOM 컬렉션 객체의 가장 중요한 특징은 \<span style="color:red">살아 있는live\</span> 객체라는 것이다. HTMLCollection은 언제나 live 객체로 동작하지만, NodeList는 경우에 따라 non-live 객체로 동작하기도 한다.

```html
// live 객체의 폐해
<ul id="fruits">
	<li class="red">Apple</li>
	<li class="red">Banana</li>
	<li class="red">Orange</li>
</ul>

<script>
  const elems = document.getElementsByClassName('red');

  // 3개의 red 요소 모두가 blue로 바뀔 것 같지만,
  for(let i=0; i<elems.length; i++)
      elems[i].className='blue';

  // Apple과 Orange만 바뀌었고 Banana는 red 존속
  // i=0일때, Apple은 blue로 바뀐다. 이때 변경된 blue는
  //  document.getElementsByClassName('red')에 속하지 않으므로 elems변수에서 제외된다.
  // 따라서 i=1일때, 기대와는 달리 banana가 아닌 Oraneg를 참조한다.
</script>
```

위 문제는 for문을 역방향으로 순회하거나, while문을 사용하는 방식으로 회피할 수 있다. HTMLCollection이 아닌 NodeList를 반환하는 `querySelectorAll` 메서드를 사용하는 방법도 있다. NodeList는 `childNodes` 프로퍼티가 반환한 객체가 아닌 경우는 non-live 객체로서 기능한다. **더 좋은 해결책은 DOM 컬렉션 객체를 사용하지 않는 것이다.** 스프레드 문법으로 DOM 컬렉션 객체를 배열로 변환하면 live 객체의 부작용도 회피할 수 있고 배열 고차함수도 활용할 수 있게 된다.

```js
[...elems].forEach(elem => elem.className = 'blue');
```

## 3. 노드 탐색
취득한 요소 노드를 기점으로 DOM 트리의 노드를 옮겨 다니며 부모/형제/자식을 탐색(traversing, node walking)해야 할 때가 있다. 이처럼 DOM 트리 상의 노드를 탐색할 수 있도록, Node, Element 인터페이스는 트리 탐색 프로퍼티를 제공한다.

> HTML 요소 사이의 스페이스, 탭, 줄바꿈(개행) 등의 공백white space 문자는 텍스트 노드를 생성한다. 이를 \<span style="color:red">공백 텍스트 노드\</span>라 한다. DOM Tree에서 노드를 탐색할 때는 이 공백 텍스트를 주의해야 한다.

#### 자식 노드 탐색

| 인터페이스  | 메서드명 | 탐색 대상 | 반환 자료구조 |
| :------------: | :-----------: | :-------------------: |   :-------------------: | 
| Node     | childNodes | 요소 노드 + 텍스트 노드 | NodeList (복수형) |
| Element    | children      |            요소 노드   | HTMLCollection (복수형) |
| Node     | firstChild | 요소 노드 + 텍스트 노드|
| Node | lastChild | 요소 노드 + 텍스트 노드|
| Element | firstElementChild | 요소 노드 | 
| Element | lastElementChild | 요소 노드 |

#### 부모 노드 탐색

`Node.prototype.parentNode` 프로퍼티를 사용한다. 부모 노드가 텍스트 노드인 경우는 없다. 텍스트 노드는 리프 노드leaf node이기 때문이다.

#### 형제 노드 탐색

| 인터페이스  | 메서드명 | 탐색 대상 |
| :------------: | :-----------: | :-------------------: |   
|   Node   | previousSibling | 요소 노드 + 텍스트 노드 |
|  Node   | nextSibling      |            요소 노드 + 텍스트 노드   |
|  Element    | previousElementSibling | 요소 노드
| Element | nextElementSibling | 요소 노드

## 4. 요소 노드의 텍스트 조작

### nodeValue

지금까지 살펴본 노드 탐색 프로퍼티가 모두 읽기 전용(getter) 프로퍼티라면, `Node.prototype.nodeValue` 프로퍼티는 setter와 getter 모두 존재하는 프로퍼티다.

노드 객체의 nodeValue 프로퍼티를 참조하면 **노드 객체의 값(텍스트 노드의 텍스트)**를 반환한다. 따라서 텍스트 노드가 아닌 요소 노드나 문서 노드의 nodeValue 프로퍼티를 참조하면 텍스트 값을 찾을 수 없으므로, null을 반환한다.

```html
<div id="foo">Hello</div>

<script>
	const foo = document.getElementById('foo');
    console.log(foo.nodeValue); // null
    
    const textNode = foo.firstChild;
    console.log(textNode) // Hello
</script>

```

### textContent

`Node.prototype.textContent` 프로퍼티는 요소 노드의 텍스트와 모든 자손 노드의 텍스트를 모두 취득하거나(get) 변경한다(set). 요소 노드의 textContent 프로퍼티를 참조하면 요소 노드의 콘텐츠 영역(시작 태그와 종료 태그 사이) 내의 텍스트를 모두 반환한다. 즉, 요소 노드의 childNodes 프로퍼티가 반환한 모든 노드들의 텍스트 노드의 값인 텍스트를 모두 반환한다. 이때 HTML 마크업은 무시된다.

```html
<div id="foo">Hello
	<span> world! </span>
</div>

<script>
	console.log(document.getElemntById('foo').textContent); // Hello world!
</script>
```nodeValue 프로퍼티는 텍스트 노드에 사용해야만 효과가 있기 때문에 활용하기가 좀 더 까다롭다. 단 textContente를 사용할때는 원하는 텍스트 노드만 조작할 수 있도록 자손 관계에 주의해야한다. `foo.firstChild.nodeValue === foo.textContent`

> `textContet`와 유사한 동작을 하는 `innerText` 프로퍼티가 있지만, 사용하지 않는 게 좋다. innerText는 CSS에 순종적이어서 CSS에 의해 비표시(vsibility:hidden)로 지정된 요소 노드의 텍스트를 반환하지 못한다. 또한 CSS를 고려해야 하므로 textContent 프로퍼티보다 느리다.

## 5. DOM 조작

\<span style='color:red'>**DOM 조작(DOM Manipulation)**\</span>은 새로운 노드를 생성하여 DOM에 추가하거나 기존 노드를 삭제 또는 교체하는 것을 말한다. DOM 조작에 의해 DOM에 새로운 노드가 추가되거나 삭제되면 리플로우와 리페인트가 발생하여 성능에 영향을 주므로, 유념해야 한다.

### innerHTML (XSS에 취약함)
`Element.prototype.innerHTML` 프로퍼티는 요소 노드의 HTML 마크업을 취득(get)하거나 변경(set)한다. 요소 노드의 innerHTML 프로퍼티를 참조하면 요소 노드의 콘텐츠 영역(시작 태그와 종료 태그 사이) 내에 포함된 모든 HTML 마크업을 문자열로 반환한다.

```html
<div id="foo"> Hello
	<span>world!</span>
</div>

<script>
	const foo = document.getElementById('foo');
    
    	// (GET) Hello <span>world!</span>
	console.log(foo.innerHTML);
    	// (SET) 기존에 있던 요소 노드의 자식 노드를 제거하고
        // 새로 작성한 HTML 마크업이 파싱되어 요소 노드의 자식 노드로 DOM에 반영된다.
    	foo.innerHTML = 'Hi <span>there!</span>;
</script>
```innerHTML 프로퍼티에 set한 HTML 마크업 문자열은 렌더링 엔진에 의해 파싱된다. 여기서 문제는, 사용자로부터 입력받은 데이터를 그대로 innerHTML 프로퍼티에 할당할 경우 크로스 사이트 스크립팅 공격(XSS)에 취약하므로 위험하다.

HTML5는 innerHTML 프로퍼티로 삽인된 `<script>` 요소 내의 JS 코드를 실행하지 않는다. 하지만 조금만 방법을 달리해도 모던 브라우저에서도 동작하는 XSS 공격을 시행할 수 있다.

innerHTML의 또 다른 단점은 HTML 마크업 문자열을 할당(set)하는 경우 요소 노드의 모든 자식 노드를 교체하는 방식이기 때문에 불필요한 DOM 변경이 많다는 것이다. 외에도 삽입 위치를 지정할수 없는 등 innerHTML은 여러모로 비효율적이다.

> `Element.prototype.insertAdjacent(position, DOMString)`은 innerHTML의 진일보된 버전이다. 기존 요소를 제거하지 않으면서 위치를 지정해서 요소를 삽입할 수 있다. innerHTML처럼 모두 지웠다가 다시 쓰는 방식이 아니기 때문에, 좀 더 속도가 빠르지만 XSS 공격에 취약하다는 점은 동일하다.

### 직접적인 노드 생성 및 추가 (createElement ~ appendChild)
innerHTML 프로퍼티가 HTML 마크업을 파싱하여 노드를 생성하고 DOM에 반영하는 방식이었다면, 노드를 직접 생성/삽입/삭제/치환해서 DOM을 조작하는 방식도 있다.

```html
<ul id='fruits">
	<li>Apple</li>
</ul>

<script>
	const fruits = document.getElementById('fruits');
    
    // 1. 요소노드 생성
    const li = document.createElement('li');
    
    // 2. 텍스트노드 생성
    const textnode = document.createTextNode('Banana');
    
    // 3. 텍스트노드를 li 요소 노드의 자식 노드로 추가
    li.appendChild(textNode);
    
    // 4. li 요소 노드를 fruits 요소 노드의 마지막 자식 노드로 추가
    fruits.appendChild(li);

</script>

```

#### a) 요소노드 생성
`Documnet.prototype.createElement(tagName)` 메서드는 요소 노드를 생성해서 반환한다.

![](https://my-personal-image-bucket.s3.ap-northeast-2.amazonaws.com/obsidian/images/velog-cd0c65e9-56c9-4151-86ac-1a59d5d2aec5-image.png)

위 그림처럼 createElement 메서드로 생성한 요소 노드는 아직 기존 DOM에 추가되지 않았고 홀로 존재하는 상태다. createElement 메서드는 요소 노드를 생성할 뿐 DOM에 추가하지는 않는다.

#### b) 텍스트노드 생성

`Document.prototype.createTextNode(text)` 메서드는 텍스트 노드를 생성해서 반환한다.

#### c) 텍스트 노드를 요소 노드의 자식 노드로 추가

`Node.prototype.appendChild(childNode)` 메서드는 매개변수 childNode에게 인수로 전달한 노드를 appendChild 메서드를 호출한 노드의 마지막 자식 노드로 추가한다. 마찬가지로, 아직 DOM에 추가되지 않은 상황이다.

![](https://my-personal-image-bucket.s3.ap-northeast-2.amazonaws.com/obsidian/images/velog-4e5cb40d-4bcd-4f98-9d8d-232e4d3852a1-image.png)

```html
<script>
  // 텍스트 노드를 생성하여 요소 노드의 자식 노드로 추가하는 일반적인 과정
  li.appendChild(document.createTextNode('Banana'));

  // textContent 프로퍼티를 활용해서 간단하게 작성한 방법
  // textContent는 모든 자손 노드를 교체하기 때문에,  요소 노드에 자손이 없을 경우에만 활용 가능
  li.textContent = 'Banana';
</script>
```

#### d) 요소 노드를 DOM에 추가

![](https://my-personal-image-bucket.s3.ap-northeast-2.amazonaws.com/obsidian/images/velog-401273c5-f8e0-468d-a75d-96c91c60ee6c-image.png)
HTML 마크업 파싱으로 생성된 기존 DOM에 `appendChild()` 메서드를 사용하면 새롭게 생성한 요소 노드를 DOM에 추가할 수 있다. 위 예제는 단 하나의 요소 노드를 생성해서 DOM에 한번 추가하므로 DOM은 한 번만 변경된다. 이때 리플로우와 리페인트가 발생한다.

### 컨테이너를 활용해서 리페인트 최소화하기
DOM에 요소 노드를 추가할 때는 `appendChild()`의 사용을 최소화해서 리페인트,리플로우 발생 빈도를 줄이는 게 좋다. \<span style="color:red">**컨테이너 요소**\</span>를 사용하면 DOM을 한 번만 변경할 수 있다. DOM에 추가해야 할 3개의 요소 노드를 컨테이너 요소에 자식 노드로 추가하고, 컨테이너 요소를 기존 DOM에 `appendChild()` 자식 노드로 추가하는 방식이다.

컨테이너 요소로 div 태그를 사용할 수도 있지만, 불필요한 컨테이너 요소(div)가 DOM에 추가되는 불상사를 피하기 위해서는 \<span style="color:red">**DocumentFragment 노드**\</span>를 사용해야 한다. DocumentFragment 노드는 문서,요소,어트리뷰트,텍스트 노드와 같은 노드 객체이지만 조금 특별한 용도의 노드로써 자식 노드들을 기존 DOM에 추가하기 위한 컨테이너 역할이다. DocumentFragment 노드를 DOM에 추가하면 자신은 제거되고 자신의 자식 노드만 DOM에 추가된다.

`Document.prototype.createDocumentFragament` 메서드는 비어 있는 DocumentFragment 노드를 생성하여 반환한다.

```html
<ul id="fruits"></ul>

<script>
    const fruits = document.getElementById('fruits');
    
    // DocumnetFragment 노드 생성
    const fragment = document.createDocumentFragment();
    
    ['Apple', 'Banana', 'Orange'].forEach(text => {
    	// 1. 요소 노드 생성
        const li = document.createElement('li');
        
        // 2. 텍스트 노드 생성
        const textNode = document.createTextNode(text);
        
        // 3. 텍스트 노드를 li 요소 노드의 자식 노드로 추가
        li.appendChild(textNode);
        
        // 4. li 요소 노드를 DocumentFragment 노드의 마지막 자식 노드로 추가
        fragment.appendChild(li);
     });
     
     // 5. DocumentFragment 노드를 fruits 요소 노드(기존 DOM)의 마지막 자식 노드로 추가
     fruits.appendChild(fragment);
     
</script>
```

위와 같이 여러 개의 요소 노드를 DOM에 추가하는 경우 DocumentFragment 노드를 사용하는 게 좋다.

### 지정한 위치에 노드 삽입하기 (insertBefore)
`appendChild`를 사용하면 항상 자신을 호출한 노드의 마지막 자식 노드로 DOM에 추가하게 된다. 즉, 위치를 지정할 수 없다. 하지만 `Node.prototype.insertBefore(newNode, childNode)` 메서드를 사용하면 위치를 지정할 수 있다. 

insertBefore 메서드는 첫 번째 인수로 전달받은 노드를 두 번째 인수로 전달받은 노드 앞에 삽입한다. 이때 중요한 건 두 번째 인수로 전달받은 노드가 반드시 insertBefore 메서드를 호출한 노드의 자식 노드여야 한다는 점이다. 그래야 자신의 자식 노드 앞에(before) 삽입하게(insert) 되는 것이기 때문이다.

### 노드 이동/복사/교체/삭제

#### 노드 이동
DOM에 이미 존재하는 노드를 appendChild 또는 insertBefore 메서드를 사용하여 DOM에 다시 추가하면 현재 위치에서 노드를 제거하고 새로운 위치에 노드를 추가한다. 즉, 노드가 이동한다.

```html
<ul id="fruits">
    <li>Apple</li>
    <li>Banana</li>
    <li>Ornage</li>
</ul>

<script>
	const fruits = document.getElementById('fruits');
    
    // 이미 존재하는 요소 노드를 취득
    const [apple, banana ] = fruits.children;
    
    // 이미 존재하는 apple 요소 노드를 fruits 요소 노드의 마지막 노드로 이동
    fruits.appendChild(apple); // Banana - Orange - Apple
    
    // 이미 존재하는 Banana 요소 노드를 fruits 요소의 마지막 자식 노드 앞으로 이동
    fruits.insertBefore(banana, fruits.lastElementChild);
    // Orange - Banana - Apple
</script>
```

#### 노드 복사
`Node.prototype.cloneNode([deep: true | false])` 메서드는 노드의 사본을 생성하여 반환한닫. 매개변수 deep에 true를 인수로 전달하면 노드를 깊은 복사deep copy하여 모든 자손 노드가 포함된 사본을 생성하고, false를 전달하거나 생략하면 노드를 얕은 복사shallow copy하여 노드 자신만의(자식 노드인 텍스트 노드 역시 미포함) 사본을 생성한다.

#### 노드 교체

`Node.prototype.replaceChild(newChild, oldChild)` 메서드는 자신을 호출한 노드의 자식 노드(oldChild)를 다른 노드(newChild)로 교체한다.

#### 노드 삭제
`Node.prototype.removeChild(child)` 메서드는 child 매개변수에 인수로 전달한 노드를 DOM에서 삭제한다. 인수로 전달한 노드는 removeChild 메서드를 호출한 노드의 자식 노드여야 한다.

 여러 개의 child를 제거하고 싶을 때, `textContent = ''`를 이용해서 한 번에 다 지울 수 있다.
 
## 6. 어트리뷰트

### 어트리뷰트 노드와 attributes 프로퍼티
HTML 요소는 여러 개의 어트리뷰트attribute(속성)를 가질 수 있다. HTML 어트리뷰트는 HTML 요소의 동작에 필요한 추가 정보를 제공하는 역할을 맡는다. HTML 어트리뷰트는 HTML 요소의 시작 태그에 `어트리뷰트 이름="어트리뷰트 값"`과 같은 형식으로 정의한다.

```html
<input id="user" type="text" value="ungmo2">
```

글로벌 어트리뷰트(id, class, style, title, lang, hidden 등)와 이벤트 핸들러 어트리뷰트(onclick, onchange, onfocus, oninput 등)는 모든 HTML 요소에서 공통적으로 사용할 수 있다. 반면 type, value, checked와 같이 input, checkbox 처럼 특정 요소에만 사용할 수 있는 어트리뷰트도 존재한다.

HTML 어트리뷰트는 HTML 문서가 파싱될 때 어트리뷰트 노드로 변환되어서 요소 노드의 형제 노드로 자리매김한다. 하나의 어트리뷰트당 하나의 어트리뷰트 노드가 생성되므로, 위 예제의 경우 하나의 요소 노드에 세 개의 어트리뷰트 노드가 붙는 형식이 된다. 이때 모든 어트리뷰트 노드는 `NamedNodeMap 객체`에 담겨서 요소 노드의 `attributes 프로퍼티`에 저장된다.

![](https://my-personal-image-bucket.s3.ap-northeast-2.amazonaws.com/obsidian/images/velog-56a74926-c0dd-488a-a5cb-e42d340193e8-image.png)

![](https://my-personal-image-bucket.s3.ap-northeast-2.amazonaws.com/obsidian/images/velog-26ade06f-0f0c-4fc6-aee5-0944b95d5a39-image.png)

\<p style="text-align:center; color:#808080; margin-top:-35px">\<i>\<요소 노드의 attributes 프로퍼티>\</i>\</p>

따라서 요소 노드의 모든 어트리뷰트 노드는 요소 노드의 `Element.prototype.attributes` 프로퍼티로 취득할 수 있다. attributes 프로퍼티는 getter만 존재하는 읽기 전용 접근자 프로퍼티이며, NamedNodeMap 객체를 반환한다.
  
```
<input id="user" type="text" value="ungmo2">

<script>
	const { attributes } = document.getElementById('user');
  	console.log(attributes);
  	// NamedNodeMap {0: id, 1: type, 2: value, id: id, type: type, value: value, length: 3}
  
  	// 어트리뷰트 값 취득
  	console.log(attributes.id.value); // user
  	console.log(attributes.type.value); // text
  	console.log(attributes.value.value); // ungmo2
</script>
  
```

#### HTML 어트리뷰트 조작

앞서 소개한 attributes 프로퍼티와는 달리`Element.prototype.getAttribute/setAttribute` 메서드를 사용하면 get/set이 자유롭다. 

```html
<input id="user" type="text" value="ungmo2">

<script>
    const input = document.getElementById('user');
    
    // GET
    const inputValue = input.getAttribute('value');
    
    // SET
    input.setAttribute('value', 'foo');
</script>
```

특정 HTML 어트리뷰트가 존재하는지 확인하려면 `Element.prototype.hasAttribute` 메서드를 사용하고, 특정 HTML 어트리뷰트를 삭제하려면 `Element.prototype.removeAttribute` 메서드를 사용한다.

### HTML 어트리뷰트 vs DOM 프로퍼티
**요소 노드 객체에는 HTML 어트리뷰트에 대응하는 프로퍼티(DOM 프로퍼티)가 존재한다.** 이 DOM 프로퍼티들은 HTML 어트리뷰트 값을 초기값으로 가지고 있다. 예를들면 `<input id="user" type="text" value="ungmo2">` 요소가 파싱되어 생성된 요소 노드 객체에는 id, type, value 어트리뷰트에 대응하는 id, type, value DOM 프로퍼티가 존재한다.

> dev tool 어디에서 DOM 프로퍼티를 찾을 수 있는건지 모르겠다.. 

DOM 프로퍼티는 setter/getter 모두 존재하는 접근자 프로퍼티다. 따라서 DOM 프로퍼티는 참조와 변경 모두 가능하다.

```html
<input id="user" type="text" value="ungmo2">

<script>
     const input = document.getElementById('user');
     
     // SET
     input.value = 'foo';
     
     // GET
     console.log(input.value);
</script>
```

**HTML 어트리뷰트의 역할은 HTML 요소의 초기 상태를 지정하는 것이다. 즉, HTML 어트리뷰트 값은 HTML 요소의 초기 상태를 의미하며 이는 변하지 않는다.**

예를 들어 `<input id="user" type="text" value="ungmo2">`를 파싱하는 상황을 생각해보자. **input 요소의 value 어트리뷰트는 어트리뷰트 노드로 변환되어 요소 노드의 atrributes 프로퍼티에 저장된다. 이와는 별도로 value 어트리뷰트의 값은 요소 노드의 value 프로퍼티에 할당된다.** 따라서 input 요소의 요소 노드가 생성되어 첫 렌더링이 끝난 시점까지는 어트리뷰트 노드의 어트리뷰트 값과 요소 노드의 value 프로퍼티에 할당된 값이 HTML 어트리뷰트 값과 동일하다.
  
```html
<input id="user" type="text" value="ungmo2">
  
<script>
	const input = document.getElementById('user');
  
  	// attributes 프로퍼티에 저장된 value 어트리뷰트 값
  	console.log(input.getAttribute('value')); // ungmo2
  
  	// value 프로퍼티에 저장된 value 어트리뷰트 값 
  	console.log(input.value); // ungmo2
</script>
```
  
하지만 첫 렌더링 이후 사용자가 input 요소에 무언가를 입력하기 시작하면 상황이 달라진다. **요소 노드는 상태state를 가지고 있다.** input 요소 노드의 경우엔 사용자가 입력한 값이 상태이고, checkbox 요소 노드의 경우엔 체크 여부가 곧 상태다.
  
사용자가 input에 foo라는 값을 입력한 경우를 떠올려보자. 이럴때 **input 요소 노드는 사용자의 입력에 의해 변경된 최신 상태(foo)를 관리해야 하는 것은 물론, HTML 어트리뷰트로 지정한 초기 상태(ungmo2)도 관리해야 한다.** 초기 상태 값을 관리하지 않으면 웹 페이지를 처음 표시하거나 새로고침할 때 개발자가 의도한 초기 상태를 표시할 수 없을 것이다.
  
  **이처럼 요소 노드는 2개의 상태, 즉 초기 상태와 최신 상태를 관리해야 한다.** 요소 노드의 초기 상태는 \<span style="color:red">**어트리뷰트 노드**\</span>가 관리하고 요소 노드의 최신 상태는 \<span style="color:red">**DOM 프로퍼티**\</span>가 관리한다.
  
어트리뷰트 노드가 관리하는 초기 상태 값을 취득하거나 변경하려면 getAttribute/setAttribute 메서드를 사용하면 된다. DOM 프로퍼티로 변경한 어트리뷰트 값은 초기 상태 값이 아닌 최신 상태 값을 변경한 것이기 때문에 getAttribute로 조회되지 않는다.
  
   > attribute는 html document/file 안에서 property 는 html DOM tree안에서 존재한다.

### data 어트리뷰트와 dataset 프로퍼티
`data 어트리뷰트`와 `dataset 프로퍼티`를 사용하면 HTML 요소에 정의한 사용자 정의 어트리뷰트와 자바스크립트 간에 데이터를 교환할 수 있다. **data 어트리뷰트는 data-user-id, data-role과 같이 data- 접두사 다음에 임의의 이름을 붙여 사용한다.**
  
data 어트리뷰트의 값은 `HTMLElement.dataset 프로퍼티`로 취득할 수 있다. dataset 프로퍼티는 HTML 요소의 모든 data 어트리뷰트의 정보를 제공하는 DOMStringMap 객체를 반환한다. DOMStringMap 객체는 data 어트리뷰트의 data- 접두사 다음에 붙인 임의의 이름을 카멜 케이스로 변환한 프로퍼티를 가지고 있다. 이 프로퍼티로 data 어트리뷰트의 값을 취득하거나 변경할 수 있다.
  
```html
  <ul class="users">
    /* data 어트리뷰트 */
    <li id="1" data-user-id="7621" data-role="admin">Lee</li>
    <li id="2" data-user-id="9524" data-role="subscriber">Kim</li>
  </ul>

<script>
    const users = [...document.querySelector('.users').children];
  
    // dataset 프로퍼티 활용
    // user-id가 '7621'인 요소 노드를 취득
    const user = users.find(user => user.dataset.userId === '7621');
    // user-id가 '7621'인 요소 노드에서 data-role의 값을 취득
    console.log(user.dataest.role) // "admin"
  
    console.log(user.dataset) // DOMStringMap {userId: "7621", role: "admin"}
</script>
```

## 7. 스타일

#### 인라인 스타일 조작
`HTMLElement.prototype.style` 프로퍼티는 setter/getter 모두 존재하는 접근자 프로퍼티로서 요소 노드의 **인라인 스타일**을 취득하거나 추가 또는 변경한다.

```html
<div style="color: red">Hello World</div>
    
<script>
  const div = document.querySelector('div');
  
  // 인라인 스타일 취득
  console.log(div.style) // CSSStyleDeclaration { 0: "color", ... }
  
  // 인라인 스타일 변경
  div.style.color = 'blue';
  
  // 인라인 스타일 추가
  div.style.width = '100px';
  div.style.height = '100px';
</script>
```

#### 클래스 조작
CSS class를 미리 정의해둔 다음 HTML 요소의 class 어트리뷰트 값을 변경하는 방식으로 HTML 요소의 스타일을 변경할 수 있다. class 어트리뷰트에 대응하는 DOM 프로퍼티를 사용해서 변경하면 되는데, 자바스크립트에서 class는 예약어이기 때문에 className과 classList DOM 프로퍼티를 통해 변경하면 된다.

`Element.prototype.className` 프로퍼티는 HTML 요소의 class 어트리뷰트 값을 취득하거나 변경한다. class 어트리뷰트 값을 문자열로 반환하므로 공백으로 구분된 여러 개의 클래스를 반환하는 경우 다루기가 불편하다.

```html
<div class="box red">Hello World!</div>

<script>
  const box = document.querySelector('.box');
  
  // .box 요소의 class 어트리뷰트 값을 취득
  console.log(box.className) // 'box red'
  
  // .box 요소의 class 어트리뷰트 값 중에서 'red'만 'blue'로 변경
  box.className = box.className.replace('red', 'blue');
</script>
```

`Element.prototype.classList` 프로퍼티는 class 어트리뷰트의 정보를 담은 DOMTokenList 객체를 반환한다. 

```html
<div class="box red">Hello World!</div>

<script>
  const box = document.querySelector('.box');
  
  // .box 요소의 DOMTokenList 객체를 취득
  console.log(box.classList)
  // DOMTokenList(2) [length: 2, value : 'box blue', 0: 'box', 1: 'blue']
  
  // .box 요소의 class 어트리뷰트 값 중에서 'red'만 'blue'로 변경
  box.classList.replace('red', 'blue');
</script>
```DOMTokenList 객체는 다음과 같이 class 어트리뷰트를 제어하는 유용한 메서드들을 제공한다. add(), remove(), item(), contains(), replace(), toggle() 등.

#### 요소에 적용되어 있는 CSS 스타일 참조
style 프로퍼티는 인라인 스타일만 반환한다. 따라서 클래스를 적용한 스타일이나 상속을 통해 암묵적으로 적용된 스타일은 참조할 수 없다. HTML 요소에 적용되어 있는 모든 CSS 스타일을 참조해야 할 경우 `window.getComputedStyle` 메서드를 사용한다.
